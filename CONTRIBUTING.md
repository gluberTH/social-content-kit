# Contributing

Keep the workflow brand-independent, local by default, and candid about evidence and tool limits. Small focused changes are easier to review.

1. Install `requirements.txt` with Python 3.10+.
2. Run `python -m unittest discover -s tests -v`.
3. Build the example into a new `output/` folder and run the validator.
4. For catalog changes, inspect mobile and desktop layouts, copy fallback, filters, image links, and no-JavaScript content.
5. Describe the observable behavior changed and the checks performed.

The committed demo is fictional. Do not add real account exports, customer records, private source snapshots, analytics, secrets, or unlicensed creative assets. Do not turn a provider-specific exception into a blanket workflow rule.

Publishing and scheduling integrations belong in explicitly authorized workflows. The default kit builder must remain offline and must not gain account access as a side effect.
